向量检索的核心流程：Embedding、索引与召回

向量检索并不是“把问题丢进去然后自动搜出来”这么简单，它背后通常有一条比较清晰的处理链路：数据向量化、索引构建、查询向量化、近邻召回，以及最终排序。

第一步：Embedding

Embedding 的作用是把文本、图片或者代码片段转换成向量。这个过程一般由预训练模型完成，比如文本嵌入模型会把一句话映射成一个高维向量。

Embedding 的质量直接影响检索效果，因为后面的所有相似度比较都建立在这个表示之上。

第二步：建立索引

如果数据量很大，不可能每次查询都和所有向量逐个比较，所以需要建立索引。常见方式包括：

  • Flat：精确检索，结果最准，但速度慢
  • IVF：先分桶再搜索，提高速度
  • HNSW：图结构近邻搜索，速度与效果通常较平衡
  • PQ：通过压缩向量降低存储与计算成本

第三步：查询向量化

当用户输入一个问题后，也需要通过同一个 Embedding 模型把查询转换成向量。这样查询和文档就处于同一个向量空间内，可以直接比较距离。

第四步：近邻召回

召回阶段会根据相似度函数找出最接近查询向量的若干条结果。常见的距离度量方式包括余弦相似度、欧氏距离和点积。

这个阶段的目标不是做最终排序，而是先快速缩小候选范围。

第五步：重排与后处理

在真实系统里，向量召回往往只是第一层。后续还会叠加关键词过滤、元数据过滤、交叉编码器重排或者业务规则排序，让最终结果更准确。

在 RAG 中的意义

RAG 系统非常依赖这条链路。只有召回内容足够准，大模型生成的答案才更可靠。也就是说，检索质量本身就是生成质量的上游保障。
